# Архитектура Telegram-ботов

Этот справочник содержит рекомендации по проектированию масштабируемых и поддерживаемых Telegram-ботов на Python (преимущественно aiogram 3.x).

## Структура проекта

Рекомендуемая структура для средних и крупных проектов:

```
bot/
├── src/
│   ├── handlers/        # Обработчики команд и сообщений (по модулям)
│   │   ├── __init__.py
│   │   ├── common.py    # /start, /help, /cancel
│   │   └── admin.py     # Админ-команды
│   ├── keyboards/       # Inline и Reply клавиатуры
│   ├── middlewares/     # Промежуточное ПО (логирование, БД, троттлинг)
│   ├── states/          # Описание состояний FSM
│   ├── filters/         # Кастомные фильтры
│   ├── services/        # Бизнес-логика и работа с API
│   ├── database/        # Модели и DAO (SQLAlchemy, Tortoise и т.д.)
│   ├── utils/           # Утилиты (форматирование, работа с файлами)
│   ├── loader.py        # Инициализация бота и диспетчера
│   └── config.py        # Конфигурация (env переменные)
├── migrations/          # Миграции базы данных
├── main.py              # Точка входа
└── requirements.txt
```

## Основные принципы

1.  **Разделение ответственности**: Хендлеры не должны содержать сложную бизнес-логику или прямые SQL-запросы. Используйте `services` и `database/dao`.
2.  **Мидлвари (Middlewares)**: Используйте их для внедрения зависимостей (например, сессии БД) и контроля доступа.
3.  **Фильтры (Filters)**: Инкапсулируйте логику проверки (например, `IsAdmin`, `HasSubscription`) в отдельные классы фильтров.
4.  **Конфигурация**: Используйте `pydantic-settings` или `python-dotenv` для управления переменными окружения.

## Работа с БД

- Используйте асинхронные библиотеки (например, `SQLAlchemy` с `asyncio`).
- Передавайте сессию БД в хендлеры через мидлвари.
- Реализуйте паттерн Repository или DAO (Data Access Object) для изоляции кода работы с БД.

## Троттлинг (Anti-flood)

Всегда реализовывайте троттлинг на уровне мидлвари, чтобы защитить бота от спама и блокировок со стороны Telegram.
